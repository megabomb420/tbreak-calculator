# Handoff — T-Break Calculator 0.28.0

Repository: https://github.com/megabomb420/tbreak-calculator · branch `main`
Live app: https://megabomb420.github.io/tbreak-calculator/

## Current product decisions

The three permanent destinations are Today, Calculator and History. Science is a separate reading screen accessible from the header and Settings. Calculator remains available during an active break, so changing goals or reading about tests never requires abandoning a plan. Recalculate starts at the goal with saved answers available; editing a specific answer still opens its specific step.

Today is the practical daily companion. The active card shows the day/target hero, the one-tap check-in with Undo, optional symptom ratings, the current phase's context ("What to expect") always visible rather than behind a toggle, one advice topic for every area the ratings flag as hard (with two stage-relevant defaults when nothing is rated), one practical activity and a manually controlled carousel of stage-matched Reddit experiences. THC-session logging exists only inside an active cut-down plan. The shared journey remains under **Your break timeline** with its existing phase windows and check-in markers. Calculator still shows the same journey as a preview. No per-day biological symptom predictions are introduced. Mark complete remains available only from the target instant. The quiet footer action is **End break early**, and the advice browser opens any guide without storing a preference. Scheduled cancellation, completed-break return plans and History keep their existing roles.

Date entry has one shared editor for intake and interruption. Native input/change events, reopening an answer, clearing a value, and switching between shortcuts and a picked date keep the visible selection and submitted value aligned. Invalid dates clear the answer and explain the problem. Start-date bounds use local calendar days, including across daylight-saving changes. The visible default of one session is accepted by Continue.

Saved calculation numbers are immutable. `saved-result.ts` advances only withdrawal/day guidance, rather than revalidating an old month's use against today's month. A live or scheduled break uses the profile from its owning calculation even after a detection query or another profile is saved. A plan reaches its target only after the full target duration has elapsed; the ring, message and completion action agree.

One shared dialog coordinator owns focus, background isolation, Escape and browser Back. Only the top dialog closes. References return to their parent; closed disclosures do not receive keyboard focus; destructive confirmations initially focus Cancel. Previous-break edits retain outcome linkage and Save & add another resets the form.

Today leads with the check-in and practical advice. The advice list is chosen only from the latest symptom ratings: every area rated hard enough is shown, hardest first, each naming its own reading, and a day with no ratings keeps two stage-relevant defaults. There are no stored preferences and no topic picker to configure; a manual browser still opens any of the eleven guides. Ratings select educational content only and never alter scientific calculations.

## Evidence decisions

The original research PDF and synced source documents were reviewed before changes. The public explainer links the human PET and withdrawal studies. The UI calls calculator ranges planning rules and labels the secondary view Recovery outlook. It explicitly identifies estimates beyond four weeks as unvalidated for direct human tolerance outcomes; animal findings do not establish human timing. No new biological numbers, numeric detection estimates, or detox/reset percentages were introduced. Numeric policies and historical results are unchanged.

This is an educational planning product. There is no clinical diagnosis, medical endpoint, jurisdiction-specific legal advice or guarantee of a negative test. Formal clinical validation of the product estimates is not claimed.

## Release 0.28.0 — storage tells the truth, and the audit is done

- **A failed save is no longer silent.** `createIndexedDbDurable` swallowed every rejected write and kept claiming persistence; nothing read `flush()`, and Settings said "Saving on this device" regardless. The durable facade now exposes `writeFailed` and `onWriteFailure`, fired once on the transition into and out of a failure, and the app renders the storage banner with `The latest change may not have been saved on this device.` while it lasts. Settings shows that same line instead of asserting a save. This is the item the audit ranked highest: a check-in, break start or session log could previously look saved and be gone after a reload.
- **A blocked or failed IndexedDB open no longer looks like an empty app.** When an IDB factory exists but the open (or the hydration that follows) fails, the facade reports itself not-persistent instead of presenting the emptied Web Storage envelopes as the user's data, so the banner says the records are not being saved here rather than showing first-launch. The database also closes itself when another tab wants to upgrade the schema (`onversionchange`), which is what makes that blocked-open case rare. The genuine no-IDB fallback is unchanged.
- **The cut-down review banner now clears.** It read the stored status as well as the derived one, so after the two breach days rolled out of the rolling week it kept claiming "your limits were crossed on two days in this rolling week" while the meters read `0 of 3`. It follows the derived state alone, matching what `CALCULATOR_SPEC.md` §593 has always documented ("derived and reversible … returns to `active` automatically"), with no write needed.
- **"Earlier today" can no longer record yesterday.** The session-log chip subtracted a flat two hours, so between 00:00 and 02:00 it wrote the session onto the previous local day — moving the use-day count, the sessions meter and possibly a breach day. It is now clamped to the start of the local day; "Now" and "Yesterday" are unchanged.
- **Accessibility and copy.** The result hero carries its accessible name again (`planHeroLabel`, "Plan for N days", previously defined and unused); the carousel dots are 44px wide per the app's own touch-target contract; the 48-hour advice freshness rule is disclosed in "How these suggestions are chosen" ("A rating stops counting after 48 hours."); and the last-use answer row formats through the shared local-day helper instead of slicing a raw stored string. That helper moved to `src/application/presentation/format.ts` so the application layer no longer reaches into `src/ui/`.
- **The evidence-posture guards cover the content they were missing.** The prohibited-claim checks now also dump the eleven advice guides, the 28 practice prompts, the 17 community cards, `research-facts.ts`, `recovery-copy.ts` and `companion-copy.ts`, plus the inline strings in `daily-support.tsx`, `community-carousel.tsx` and `predicted-reset.tsx`. The percentage rules are scoped to *personal* promises, because `recovery-copy.ts` legitimately quotes a study finding ("about 15% lower than baseline availability"). Nine prohibited samples are asserted to be caught and eight legitimate quotes asserted to pass.
- **Local-calendar behaviour is tested, not assumed.** `npm run test:tz` re-runs both runners under `America/Los_Angeles` and `Europe/Berlin` (via `--env-file`, since a shell-assigned `TZ` is ignored on Windows) and CI runs that pass, with new DST-transition coverage for `planStartBounds`/`resolvePlanStartDate` and for reduction day grouping across the change. The first non-UTC run surfaced two UTC-hardcoded test expectations; both were test assumptions rather than source bugs, and both now derive the expected local day.

Validation: the default suite passes (**596 unit/domain/golden tests and 197 UI tests**, 3 TZ-gated cases skipped), and both non-UTC passes are green — Pacific **602 + 200**, Europe/Berlin **596 + 197** — plus typecheck and the production build. Every fix above landed with a test that fails before it.

The whole-product audit that `HANDOFF` listed as outstanding is now done. It found no blocker and nothing in the categories it verified sound (backup contract and rejected-file classes, check-in integrity, profile validation and the 30-day rules, the single day clock, dialog/focus coordination, carousel, advice selection, reduction day grouping, touch targets, contrast). Four findings are **not** fixed and need the owner: the first-launch safety slot still lacks the age, health and urgent-help content `UX_SPEC` §130 and `CALCULATOR_SPEC` §653–659 call a release blocker (the repo's rule is not to invent safety copy); reduction day grouping still applies today's UTC offset to past events, which a DST change can re-bucket (the fix is storing the offset per event, a versioned schema change); one latent flow can be set while rendering no dialog (unreachable from the UI today); and the uncapped advice list has no floor, so a single hard rating shows a single topic.

## Release 0.27.1 — a closed disclosure says it is closed

- **The disclosure marker was inherited from the wrong element.** `.result-disclosure`'s summary rules were descendant selectors, so an open disclosure also applied its own "open" marker — and its 18px display typography — to every summary nested inside it. In practice, opening **Your break timeline** made each of its closed phase legs show "–" as if expanded, and pushed them from their intended small muted text up to the large display face. The rules are now scoped to the disclosure's own summary (`> summary`), and the phase legs carry their own marker pair plus the layout they were relying on, so each disclosure reports its own state.
- No content, behaviour, storage or copy changed. Measured in a real browser at 390px before and after: three nested legs closed showed `font-family: Fraunces, 18px, marker "–"` before and `Figtree, 13px, marker "+"` after; with one leg opened, only that leg reads "–" and the other two stay "+". The outer "Your break timeline" heading is unchanged at Fraunces 18px with its own marker.

Validation: **580 unit/domain/golden tests and 186 UI tests (766 total)** pass, plus typecheck and the production build.

## Release 0.27.0 — advice follows your check-ins, not a settings screen

- **The topic picker is gone.** "Choose advice topics" and the whole personalisation flow are removed — from the Today cards, the result screen and the plan guide — together with the copy and the CSS that only fed them. Advice is no longer something to configure.
- **The two-topic cap is gone.** The "What matters today" list is now exactly what the latest ratings flag: every area at the oriented threshold or harder, hardest first, each naming its own reading ("Sleep quality 2/10 in your check-in"). The five rating fields bound it at five. A day whose ratings flag nothing — no ratings yet, or only comfortable ones — keeps two stage-relevant defaults, and a comfortably rated area is still never offered as a problem. The rating rules themselves are untouched: latest non-null value per field, within 48 hours, inside the current segment, later "No THC" taps never erasing a rating, sleep and appetite inverted.
- **What this deliberately drops.** The picker was how someone steered advice without rating anything, and the cap kept the card short. Both were reversed because the ratings are the honest input and the cap was hiding advice the user had in fact asked for. The stored `companion-personalisation.v2` record is kept — schema, migration and its place among the backup's ten families untouched — but nothing reads it for selection any more, so an existing device's saved topics are simply no longer consulted. The advice browser ("Help with something else") is unchanged: it opens any of the eleven guides and stores nothing. The content layer is bumped to **`daily-support-v3`** under the §14 change-control rule.

Validation: **580 unit/domain/golden tests and 186 UI tests (766 total)** pass, plus typecheck and the production build. New coverage: four hard ratings produce four advice topics in severity order (the old cap produced two), an unrated day keeps two stage-relevant defaults, a comfortable rating keeps its area out of that pair, and the UI suite drives the real check-in form to the same result. Verified in a real browser at 390px: two defaults before rating, then four topics after rating sleep 2 / craving 8 / anxiety 7 / irritability 6, each with its own reason line, no horizontal overflow and no console error.

## Release 0.26.1 — the phase context stays open

## Release 0.26.0 — your data in a file, and the outlook during a break

- **Local backup (new).** Settings gains a **Your data** section with **Save a backup file** and **Restore from a backup file**. The export is one pretty-printed JSON file, `tbreak-backup-YYYY-MM-DD.json`, whose envelope is `{ format, formatVersion, appVersion, exportedAt, data }`; `data` carries ten record families — saved answers, frozen calculations, break attempts, tracking runs, check-ins, past breaks, cut-down plans with their use logs, legacy saved limits, break ratings and support areas — each payload exactly what that store's own `load()` returns. Restoring validates **every** payload with the store's own load-time parser before writing anything, so a damaged, foreign or partially-valid file changes nothing, then replaces everything behind a danger-styled confirmation that lists per-store counts and states plainly that the current data cannot be brought back. Missing store keys mean empty; an unknown `format` and a newer `formatVersion` are refused with their own messages. Excluded on purpose: the unfinished questionnaire draft, the transient result-overlay flag, the derived post-break mirror (rebuilt from the attempt rows on every write), the one-off migration marker, and rows that were already corrupt on the old device. One registry drives export, validation, counts and import, and a typed label map plus two tests make a newly added store fail loudly rather than silently escape the file. The copied file is not encrypted and holds everything the app knows about the user; the Settings hint says so.
- **Recovery outlook during a break.** The outlook was reachable from the result screen, from History, and from Today/Calculator before a break started — but not while one was running, which is when it is wanted. It is now a closed **Recovery outlook** disclosure inside the active-break card, after the timeline, rendering the same panel with the same check-in facts: no new copy, no new numbers. It appears only for a calculated break that owns a calculation record — a chosen-duration break, an open-ended tracking plan, or a break whose record is missing renders exactly as before.
- **Carousel position.** The visible Reddit card is tracked by card identity instead of slot number, so re-ranking the list — which happens on every check-in save and topic change — no longer swaps the card under the reader, and the counter follows the card to its new place. The arrows also move the card immediately rather than depending on a scroll event arriving, so they are no longer inert on a track with no measured width. Verified against the pre-fix component: with the old code the new regression fails by reproducing the swap.
- **Outcome duration.** The past-break record created from a captured rating now stores the days actually abstained (summed from the attempt's segments) instead of the plan's `targetDurationDays`, falling back to the target when the segments yield no elapsed day. The rating describes the abstinence that happened, and that is the number the tolerance engine's history insight reads. Forward-only: stored past breaks and frozen results are untouched, and History still shows the plan's name with the real duration beside it.

Validation: **578 unit/domain/golden tests and 186 UI tests (764 total)** pass, plus typecheck and the production build. New coverage: 25 backup unit tests (round-trip into an empty app, replace-not-merge, derived-mirror rebuild, twelve rejected-file classes each asserting the target state is byte-identical afterwards, plus the two coverage guards) and 13 backup UI tests (both actions, export contents, the confirmation with counts, nothing written before confirming, a real restore flipping Today and History, cancel, invalid files, and the browser plumbing). One limitation is documented rather than fixed: the restore wipes before it writes, so an I/O failure mid-write is the single case that is not atomic — a rejected file never is.

## Release 0.25.1 — consistency pass (closes the 0.25.0 round)

No screen, flow, engine number or stored contract changed. This release retires the adaptive-recalculation path that 0.25.0 had already disconnected, and brings documentation, tests and styles back in line with the shipped app.

- **Adaptive recalculation is retired in code as well as in behaviour.** The 0.25.0 round removed its only caller (the cut-down refresh sheet, the in-card tolerance comparison and `runAdaptiveRecalc`), which left `src/application/calculation/adaptive-recalc.ts`, `src/application/presentation/reduction-trajectory.ts`, the domain helpers behind them (`observedPattern`, `observedDiffersFromBaseline`, `rangeWithinEvidenceBounds` and their constants) and their unit suites orphaned and green. All are deleted. Logging a session in a cut-down plan never generates, refreshes or rewrites a calculation record; frozen records stay immutable.

The retained rendering branch and its copy are now labelled legacy-only in the code instead of looking like dead weight.
